# Transfer existing data to Railway

The private export is stored under `backups/` (excluded from Git). It includes
database records, primary keys and relationships, plus Chroma chat documents,
metadata, IDs and embeddings. Do not upload the export to a public repository.

## Export

Pause local writes while making the final export so Django and Chroma represent
the same point in time. Use a new directory for each export:

```powershell
python scripts/transfer_railway_data.py export backups/railway-final
```

The script backs up SQLite through its backup API, exports portable Django and
Chroma JSON files, and writes counts and SHA-256 checksums to `manifest.json`.
Content types and permissions are regenerated by Django migrations. Local source
files are not overwritten. Browser sessions are included, but session cookies
may not carry over to another domain or Django secret key.

## Import PostgreSQL

Create a pgvector-enabled PostgreSQL database. Temporarily pause Railway app
writes, including background scraping, while transferring data. In local `.env`
set `RAILWAY_DATABASE_URL` to the database service's `DATABASE_PUBLIC_URL` (the
external TCP proxy URL, not the private `railway.internal` URL).

```powershell
python scripts/transfer_railway_data.py import-db backups/railway-final
```

The script checks that the destination has no user/application data, enables
the vector extension, migrates the schema, and loads data in one transaction.
It checks model counts and resets PostgreSQL ID sequences before committing.
It never deletes existing rows. If the destination already has content, stop
and plan a merge or choose an empty database; do not flush production data.

The Railway application and importer must point to the same database. A running
app is not required for the import. Remove the temporary local connection
variable after the transfer if it is no longer needed.

## Import Chroma on the Railway app host

Attach a persistent volume at `/data` and configure:

```dotenv
CHROMA_PERSIST_DIRECTORY=/data/chroma_db
```

Securely transfer `manifest.json`, `chroma-data.json` and `django-data.json` to
a private directory on the app host. Run the importer inside the deployed app
container with the persistent volume mounted, while the app is not writing:

```bash
python scripts/transfer_railway_data.py import-chroma /data/private-import --chroma-destination /data/chroma_db
```

The destination must not already contain collections. Verify record counts,
news pages, service records and past consultations before reopening writes.
Export and restore were validated locally; PostgreSQL import still requires
the live Railway connection and a separate validation there.
